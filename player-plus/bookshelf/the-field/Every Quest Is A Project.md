# Every Quest Is A Project

*A Quest is framed and planned like work, not wished. Everything is a project; the only question is whether it is managed like one.*

The claim is simple and unpopular: the garden, the meal train, the repair of a broken relationship between two Cells — each has an end state, a set of things that must happen first, people who hold them, and a date. Calling it a Quest makes it noble; treating it as a project makes it finish.

It is load-bearing because it connects the table to the production disciplines. Once a Quest is a project, [[Pull planning]] applies to it (plan backward from the end, not forward from today), [[The look-ahead]] applies (what could stop this from being ready?), [[Constraint]] removal applies, and [[Conditions of satisfaction]] can be written by whoever receives the work. Without this move, a Cell's good intentions never become reliable results, which is the failure [[Networks of Commitments]] exists to prevent.

How it is played, at the smallest honest scale. Write the end state as the *done when* line on [[The Questcard]]. List what must happen, roughly, and in what order. Name one holder per line and a finish-by date. Each week, look a few weeks ahead and clear what would block the next pieces. Release only work that can actually be done into the week's commitments. At the turning, check the *done when* line rather than the feeling. A three-person Cell does all of this on one card and in one conversation; a larger body does the same thing with [[Work Breakdown Structure]], [[The activity table]], and [[Milestone]]s — the discipline is the same size as the work.
